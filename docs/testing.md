# Проверка перед релизом

Автоматические тесты запускаются при каждой сборке на GitHub, но у серверов GitHub нет звуковых карт.
Поэтому то, что зависит от настоящих устройств, проверяется руками — это минут 15–20. Всё, что программа
замечает, она пишет в журналы в `%APPDATA%\VolumeGuard\`: `limiter.log` (лимиты приложений) и `audio.log`
(обработка звука). Проверка сводится к «сделал → посмотрел, что написано в журнале и что слышно».

## Что проверяется автоматически

| Где | Что |
|---|---|
| `tests/LimiterTests.cs` | Лимит приложений: три режима, скорость возврата, память громких звуков, тишина, низкие лимиты (−40/−60 дБ), несколько потоков, испорченный `settings.txt` |
| `plugin/tests/test_limiter.cpp` | Лимитер с взглядом вперёд: потолок держится на 44,1/48/96 кГц, в том числе без страховочного обрезания |
| `plugin/tests/test_game.cpp` | Comfort / Tactical: выстрелы тише, шаги громче, направление звука не меняется |
| `plugin/tests/test_chain.cpp` | Никаких щелчков при смене потолка, усиления, режима, Bypass; страховочное обрезание не срабатывает |
| `native/tests/test_bridge.cpp`, `test_pump.cpp` | Связь двух устройств: дрейф часов, разные частоты, неровные пакеты, опоздания потока, пауза источника |
| `native/tests/test_processor.cpp` | Форматы звука, весь путь 5.1 → стерео, сглаживание разрывов |
| `native/tests/smoke.cpp` | `vgaudio.dll` загружается на Windows и правильно отвечает на ошибки |
| pluginval | Плагин в настоящем хосте VST3, максимальная строгость |

## Ручной чек-лист

Нужны: VB-CABLE (или свободный выход), наушники, любая игра или видео с резкими звуками.

### Лимиты приложений (главное окно)

- [ ] Включить лимит у игры. Громкий звук после тишины: громкость убавляется, в `limiter.log` есть строка
      про устройство («volume in hardware/software»).
- [ ] «Без щелчка» включён, режим «По пикам»: при резком звуке в `limiter.log` появляется `anti-click`.
- [ ] Переключить «По пикам» → «По громкости» → «Плавно», «Быстро» → «Медленно»: поведение меняется сразу, без перезапуска.
- [ ] Поменять громкость игры в микшере Windows: программа принимает её как новую (ползунок в окне следует).
- [ ] Закрыть VolumeGuard через трей во время сильного ограничения: громкость игры возвращается.
- [ ] Выдернуть наушники и вставить обратно: карточки приложений восстанавливаются за пару секунд.

### Обработка звука

- [ ] Включить: внизу окна «Работает», задержка и её разбивка. Записать цифры.
- [ ] 30 минут игры: счётчик пропусков не растёт после первых секунд; в `audio.log` нет `output queue ran low`
      после начала (или единицы).
- [ ] Двигать «Потолок», «Усиление», «Сила», переключать режимы во время звука: никаких щелчков.
- [ ] Пауза в игре на 10 с и снова звук: звук возвращается без щелчка (в журнале может быть `sound again after`).
- [ ] Выдернуть наушники во время игры и вставить обратно: «переподключаемся…», потом снова «Работает».
- [ ] Сменить частоту наушников в свойствах звука Windows (48 ↔ 44,1 кГц): обработка переподключается сама.
- [ ] Сон и пробуждение компьютера: через несколько секунд снова «Работает».
- [ ] «Направить игру сюда» → игра → «Направить в CABLE Input»: звук игры идёт через обработку
  (в «Громкости приложений» Windows у игры стоит CABLE Input). «Вернуть на устройство по умолчанию» — обратно.
- [ ] «Включать, пока запущена …»: закрыть игру — через 2 с обработка выключается, запустить — включается.
- [ ] Ctrl+Alt+P, Ctrl+Alt+M, Ctrl+Alt+L из игры: переключается, у трея короткое уведомление.

### Плагин

- [ ] FL Studio / Reaper: плагин открывается с окном, Bypass и режимы переключаются без щелчков.
- [ ] Пресеты SHOOTER / MOVIE / NIGHT в окне и в списке пресетов программы; график ослабления движется.
- [ ] Wave Link: плагин на канале игры, индикаторы IN/OUT двигаются, звук есть.

Нашли проблему — приложите `limiter.log`, `audio.log` и `crash.log` (если есть) к issue на GitHub.
